# CLAUDE.md

Контекст проекта для Claude Code. Читать целиком перед первой правкой.

---

## Что это

Локальный сайт «Терминал» для повторения языка программирования. Учебный
модуль детской IT-школы KIBERone, **старшая группа, дети 12–14 лет**.
Два занятия по два часа: первое на Python, второе на C#.

Ребёнок читает короткую теорию с запускаемыми примерами, тут же решает задачи
в редакторе, сайт проверяет решение тестами. На проекторе висит общая таблица
движения группы.

Восемь тем по три задачи. **Две версии одного курса — Python и C#, задачи
совпадают один в один по `id` и формулировке.** На занятии по C# ребёнок видит
рядом собственное решение той же задачи на Python, написанное неделю назад.
Это и есть ответ на вопрос «чем языки отличаются» — не лекция, а свой же код
в двух колонках.

Пользователей двое: **ребёнок** (решает) и **тьютор** (запускает сервер,
выводит таблицу на проектор, видит, кто где застрял).

Полное исходное задание лежит на уровень выше репозитория:
`../ПРОМТ для сайта Терминал (Python и C#).md`. В репозиторий не входит.
Если оно доступно — оно главнее этого файла.

## Жёсткие ограничения

Нарушать нельзя. Это не стилевые предпочтения, а требования заказчика.

1. **Никакого ООП.** Ни классов, ни объектов, ни методов — в теории, задачах
   и примерах. За два года эти дети писали на Python процедурно, а впереди
   у них 12 занятий C#, где классы разбираются с нуля и подробно.
   В C# `class Program` присутствует как обязательная **рамка языка**,
   решения пишутся как `static`-методы внутри неё, и в теории это подаётся
   именно так: «рамка, внутри которой мы пишем функции». Слова «класс»,
   «объект», «экземпляр», «метод класса» не употребляются.
   Есть тесты `test_no_oop_anywhere_in_python` и `test_csharp_frame_is_only_frame`.

2. **Никаких обращений к внешним хостам.** В классе может не быть интернета.
   Skulpt и CodeMirror вендорены в `server/static/vendor/` и лежат в репозитории.
   Не заменять на CDN, не добавлять новые внешние ресурсы, не подключать шрифты
   с Google Fonts — только системные.

3. **Задачи описываются данными, а не кодом.** Один JSON на тему.
   Ни одна задача не хардкодится.

4. **Детям не показывается время решения.** Нигде. Оно есть ровно на странице
   тьютора, в списке «кто где сидит». Причина: если считать скорость, через
   двадцать минут трое уедут вперёд, а остальные перестанут стараться.

5. **Голый traceback ребёнку не показывается.** Ошибки переводятся на русский
   и всегда с номером строки **в его коде**.

6. **Никакой сборки фронтенда.** Ванильный JS, ES5-совместимый стиль
   (`var`, `function`, без стрелок и классов), без фреймворков и npm.

Чего сознательно нет и добавлять не надо: регистрации и паролей, скачивания
решений файлом, просмотра чужого кода, просмотра кода ребёнка тьютором,
автодополнения и линтера в редакторе, чата и комментариев, хранения данных
между учебными годами.

## Команды

```
python server/app.py            # запуск, печатает адрес крупно
python tools/check_content.py   # 196 тестов на эталонных решениях, обязательно после правки задач
python -m pytest tests -q       # 88 тестов
```

`check_content.py` **падает**, если .NET SDK не установлен: он не притворяется
успешным, когда половина курса не проверена. Это не баг.

.NET SDK ищется в `PATH` и в `%USERPROFILE%\.dotnet` (установка без прав
администратора). Первый запуск прогревает компилятор ~30 секунд.

## Архитектура

**Python исполняется в браузере через Skulpt.** Из этого следует главное
свойство системы: **урок не умирает вместе с сервером**. Проверка задач идёт
локально, поэтому при падении сервера или потере сети дети продолжают решать —
гаснет только общая таблица, и сайт прямо говорит об этом плашкой. Отправки
прогресса ждут в очереди в `localStorage` и уходят, когда сервер вернётся.

Pyodide не используется: 10+ МБ на каждого ребёнка через один классный Wi-Fi.
Blazor и Roslyn в браузере — по той же причине.

**C# компилируется на машине тьютора.** Сервер принимает код, подставляет его
в готовый проект, собирает и запускает с таймаутом.

**Сервер** — FastAPI + uvicorn, хранилище SQLite-файл рядом со скриптом.

```
Ребёнок → topic.html
            ├─ Python: runner.js → Skulpt (в браузере)      ← сервер не нужен
            └─ C#:     net.js → POST /api/run → runner_csharp.py → dotnet build
          net.js → POST /api/progress → db.py → SQLite
                                          ↓
                     board.html / tutor.html ← GET /api/board (опрос 3 с)
```

### Файлы

| Что | Где |
|---|---|
| Логика страницы темы, проверка, сцена сдачи | `server/static/app.js` |
| Запуск Python, перевод ошибок Skulpt на русский | `server/static/runner.js` |
| Связь с сервером, очередь при обрыве, плашка офлайна | `server/static/net.js` |
| API, маршруты, валидация | `server/app.py` |
| Схема и запросы | `server/db.py` |
| Компиляция C#, разбор ошибок, номера строк | `server/runner_csharp.py` |
| Таблица на проектор | `server/static/board.js` |
| Страница тьютора | `server/static/tutor.js` |
| Палитра, типографика, вся вёрстка | `server/static/style.css` |

### API

`GET /api/topics/{lang}` — список тем с пометкой, какие готовы
`GET /api/content/{lang}/{topic}.json` — тема целиком
`POST /api/session` — `{name}`
`POST /api/activity` — `{name, lang, task_id}`, отмечает, на какой задаче сидит
`POST /api/progress` — `{name, lang, task_id, solved, hints, code}`, идемпотентно
`POST /api/run` — `{lang: "csharp", task_id?, code}`, компиляция и запуск
`GET /api/solution/{lang}/{task_id}?name=` — своё решение прошлого занятия
`GET /api/board?lang=` — таблица, **без времени**
`GET /api/tutor?lang=` — то же плюс время
`GET /api/runtime` — есть ли .NET SDK

`Net.push()` ставит в очередь при обрыве связи. `Net.send()` — нет: для запуска
кода ответ нужен здесь и сейчас, а отложенная компиляция никому не нужна.

## Инварианты, которые нельзя ломать

**Номера строк в ошибках C#.** Заготовка с вызовами тестов приписывается
**после** кода ребёнка, перед его последней фигурной скобкой. Поэтому его
строки не сдвигаются ни на одну. Не вставляйте ничего выше кода ребёнка
в `build_source` — иначе номера поедут и вся польза пропадёт.
Сторожит `test_csharp_source_keeps_student_line_numbers`.

**Соответствие языков один в один.** У задачи на C# тот же `id`, тот же
заголовок, те же аргументы и ожидания тестов, что у Python. По `id` сайт
связывает решения между занятиями. Сторожат `check_parity` и
`test_languages_match_one_to_one`.

**Ровно один скрытый тест на задачу.** Обычно граничный случай. Он не даёт
подогнать под ответ и учит думать про края.

**Две-три подсказки на задачу.** Открываются по одной.

**Идемпотентность `/api/progress`.** Повторная отправка ничего не ломает,
решённая задача обратно в нерешённые не уходит, время сдачи не переписывается.

**Валидация на границе.** `task_id` проверяется по контенту: клиент не может
придумать задачу. Имена нормализуются (`Аня` и `аня` — один ребёнок).

## Грабли

**Skulpt — не CPython.** `"м".isalpha()` возвращает `False`: эти методы
работают только с латиницей. Курс написан по-русски, поэтому решение
на `isalpha()` проходит `check_content.py` и молча врёт в браузере у ребёнка.
Поймано на `dicts-1`.

`check_content.py` теперь ругается на `isalpha`, `isdigit`, `isupper`,
`islower`, `isspace`, `isalnum` в решениях и подсказках. **Если добавляете
задачу с русским текстом — не опирайтесь на эти методы, и проверьте её
руками в браузере:** прохождение на CPython ничего не доказывает.

**Атрибут `hidden` и CSS.** Правило вида `display: flex` перебивает `hidden`,
и элемент показывается, когда не должен. Напарывался дважды. Для каждого
скрываемого блока нужно `.класс[hidden] { display: none; }`.

**Автозакрытие скобок в CodeMirror снято намеренно.** Оно убирает ровно ту
ошибку `CS1513: } expected`, которую теория C# учит читать. Не возвращать.

**Heredoc в bash ломается на длинном содержимом** с кавычками — при правке
файлов из шелла пользуйтесь Write/Edit, а не `cat <<EOF`.

**`\n` в подстановках.** При генерации кода скриптом легко получить настоящий
перенос вместо escape-последовательности и сломать файл. Проверяйте
`python -c "import ast; ast.parse(...)"` и `node --check`.

## Как добавить или изменить задачу

1. `content/python/<тема>.json` → дописать в `tasks`.
2. `content/csharp/<тема>.json` → та же задача **с тем же `id`**, заменить
   `starter`, `solution`, `entry`, добавить `signature`.
3. `python tools/check_content.py`.

Поля задачи: `id`, `topic`, `title`, `statement`, `starter`, `entry`, `tests`,
`hints`, `solution`. Необязательные: `must_call`, `signature` (только C#).

`signature` нужен, чтобы сгенерировать литералы аргументов C#. Поддерживаются
`int`, `long`, `double`, `bool`, `string`, `int[]`, `string[]`,
`dict` (это `Dictionary<string, int>`).

`must_call` — если задача обязана вызывать свою же функцию (как `primes_up_to`
вызывает `is_prime`). Это единственное требование, которое тестами по
результату не поймать, поэтому оно проверяется по исходнику и показывается
отдельной строкой в списке тестов.

Темы и их порядок: `basics`, `conditions`, `loops-for`, `loops-while`,
`lists`, `strings`, `functions`, `dicts`. Порядок задан в коде
(`TOPIC_ORDER` в `server/app.py` и `server/static/app.js`), он учебный,
а не алфавитный.

## Стиль

**Код на английском, интерфейс и комментарии на русском.** Имена функций
в задачах английские: Python — `snake_case`, C# — `PascalCase` (это
соглашение языка, и дети увидят его на следующих 12 занятиях).

**Комментарии объясняют «почему», а не «что».** Если решение неочевидное или
принято вопреки очевидному — это надо записать. Пересказывать код словами
не надо.

**JS в стиле ES5:** `var`, `function`, без стрелок, классов и `let`.
Так же написан весь существующий код.

**Тексты для детей.** Пишутся от лица интерфейса, активным залогом, без
восклицательных знаков, без сюсюканья и без извинений. Ошибка говорит, что
случилось и что делать: «Строка 4: имя `numbrs` не определено. Проверь, как
ты назвал переменную выше». Пустой экран — приглашение к действию.

## Оформление

Фирменные цвета KIBERone взяты из логотипа: жёлтый `#F9CA00`, бирюза
`#0BB4B9`, глубокий синий `#004F6A`, почти-чёрный `#070009`.

**Правило палитры: жёлтый — сигнальный цвет состояния.** Он показывает
«где я сейчас» и «что сейчас произошло», и не используется для украшения.
Одна жёлтая кнопка на странице, жёлтый узел у открытой карточки, жёлтый штамп
сдачи. Внутри редактора жёлтый отдан ключевым словам языка — это отдельный
контекст.

**Бирюза — цвет «провода»:** прогресс, фокус, пройденный тест. Зелёного
в бренде нет, и он не нужен: пара бирюза/красный вдобавок различима при
дальтонизме, а форму несут значки `✓` и `✕`.

**Типографика: машина говорит моноширинным, человек — гротеском.** Метки,
числа, имена функций, кнопки — Consolas/Cascadia. Проза теории — Segoe UI.
Шрифты только системные.

**Индикатор курса** в шапке — восемь сегментов по три насечки, то есть
буквально восемь тем по три задачи. Тот же язык квадратных насечек повторён
на «шине» слева, которая соединяет карточки теории.

**Момент сдачи** (конфетти запрещено заданием): тесты догорают бирюзой
по одному с задержкой 170 мс, затем по панели один раз проходит жёлтая строка
развёртки, рамка защёлкивается, встаёт штамп «Задача сдана», наверху вспыхивает
и оседает новая насечка курса. Одна собранная секунда.

Целевой экран — **ноутбук 1366×768**, это самый вероятный класс. Проектор —
1920×1080, но бывает и 1280×720. Всё интерактивное имеет видимый фокус
и состояние нажатия. `prefers-reduced-motion` уважается.

## Проверка работы

Сборка и типы ничего не доказывают. Перед тем как считать UI-задачу
сделанной — **открыть в браузере и посмотреть**.

В репозитории нет автотестов на вёрстку. Для проверки вживую удобно поднять
сервер и снять экран через headless Chrome по CDP (Node 22+ умеет
`WebSocket` без зависимостей): навигация, `Runtime.evaluate` для нажатий,
`Page.captureScreenshot`. Так были найдены минимум три ошибки, которых
не видно из кода: ловушка `isalpha` в Skulpt, конфликт `hidden` с `display`,
и тема, помеченная закрытой на странице, которую ребёнок уже читает.

Что смотреть обязательно: пустое состояние, состояние ошибки, самый длинный
контент, экран 1366×768.

## Сеть в классе

Во многих гостевых Wi-Fi включена изоляция клиентов — тогда ноутбуки детей
не видят машину тьютора вообще, и настройками сайта это не лечится.
Проверять за день. Запасной вариант — точка доступа с телефона тьютора.
Ngrok и туннели в проекте не используются.

## Осознанные размены

**Проверка идёт в браузере, поэтому результат можно подделать через консоль.**
Взамен получаем работу без сервера и мгновенный отклик. Таблица считает
прогресс, а не победу, так что цена накрутки невелика.
**В README не писать, что результаты защищены от подделки.**

**Запуск C# — не песочница.** Расчёт на детей и случайные бесконечные циклы,
а не на злонамеренный код: таймаут 10 секунд, вывод обрезается до 10 КБ,
работа во временной папке. В README так и написано.

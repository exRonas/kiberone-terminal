# Промт: «Терминал» — сайт для повторения Python и C#

> Скопировать целиком в новый чат Claude Code. Больше ничего прикладывать не нужно.

---

Мне нужен локальный сайт, на котором дети 12–14 лет повторяют язык программирования:
сначала читают короткую теорию с живыми примерами, потом тут же решают задачи в редакторе
кода, а сайт сам проверяет решение тестами. На проекторе висит общая таблица прогресса
группы.

Нужны две версии одного и того же сайта: на Python и на C#. Темы и задачи в них
совпадают один в один — в этом весь смысл. На занятии по C# ребёнок видит рядом
собственное решение той же задачи на Python, которое он написал неделю назад.

Это учебный модуль детской IT-школы KIBERone, старшая группа. Два занятия по два часа:
первое на Python, второе на C#.

## Главное ограничение: никакого ООП

За два года эти дети писали на Python процедурно. Впереди у них 12 занятий C#,
где классы и объекты будут разбираться с нуля и подробно. Здесь их не должно быть
вообще: ни в теории, ни в задачах, ни в примерах.

В C#-версии `class Program` присутствует как обязательная рамка языка, а все решения
пишутся как `static` методы внутри неё. В теории это подаётся именно так: «это рамка,
внутри которой мы пишем функции». Слова «класс», «объект», «экземпляр», «метод класса»
не употребляются.

## Кто пользуется

| Кто | Что делает |
|---|---|
| **Ребёнок** | Открывает сайт в браузере, читает теорию, решает задачи, видит свой прогресс |
| **Тьютор** | Запускает сервер, выводит таблицу группы на проектор, видит, кто где застрял |

Регистрации и паролей нет. Ребёнок вводит своё имя один раз, оно запоминается
в `localStorage`. Данные живут два занятия и стираются.

## Архитектура

**Python исполняется в браузере через Skulpt.** Skulpt — лёгкий транспайлер Python в JS,
около мегабайта, вендорится локально. Библиотек он не поддерживает, но задачи их
не используют. Ограничение времени выполнения — `Sk.execLimit`, чтобы бесконечный цикл
не вешал вкладку.

Из этого следует главное свойство: **урок не умирает вместе с сервером**. Проверка задач
идёт локально в браузере. Если сервер упал или пропала сеть, дети продолжают решать —
пропадает только общая таблица. Сайт должен явно это показывать: маленькая плашка
«таблица недоступна, решения сохраняются локально».

**Не используй Pyodide.** Он честнее, но весит больше 10 МБ на каждого ребёнка через
один классный Wi-Fi и грузится несколько секунд. Для наших задач Skulpt достаточен.

**C# исполняется на сервере.** На машине тьютора установлен .NET SDK. Сервер принимает
код, компилирует во временную папку, запускает с таймаутом и возвращает результат.
Blazor и Roslyn в браузере не используем — это десятки мегабайт на клиента.

**Сервер** отдаёт статику, хранит прогресс и решения, компилирует C#. FastAPI + uvicorn.
Хранилище — SQLite-файл рядом со скриптом, ничего разворачивать не нужно.

## Страница темы

Экран делится на две колонки.

**Слева — теория.** Три-четыре карточки, каждая с одним понятием и живым примером.
Пример можно запустить прямо в тексте и изменить — он выполняется тем же Skulpt.
Теория короткая: одна карточка помещается на экран без прокрутки.

**Справа — задача.** Формулировка, редактор кода со стартовым шаблоном, кнопка
«Проверить», под ней список тестов. Тесты загораются зелёным по одному с небольшой
задержкой между ними — это заметно приятнее, чем показать результат разом.

Под задачей — кнопка «Подсказка». Подсказок две-три, открываются по одной, каждая
стоит балл. Ребёнок сам решает, помучиться ещё или взять.

Порядок работы ребёнка: прочитал теорию → решил три задачи темы → тема закрыта,
открывается следующая. Темы идут по порядку, но вернуться к пройденной можно всегда.

## Формат задачи

Все задачи описываются данными, а не кодом. Один JSON-файл на тему.

```json
{
  "id": "loops-for-2",
  "topic": "loops-for",
  "title": "Обратный отсчёт",
  "statement": "Напиши функцию, которая по числу n возвращает список чисел от n до 1.",
  "starter": "def count_down(n):\n    # твой код\n    ",
  "entry": "count_down",
  "tests": [
    { "args": [5], "expect": [5, 4, 3, 2, 1] },
    { "args": [1], "expect": [1] },
    { "args": [0], "expect": [], "hidden": true }
  ],
  "hints": [
    "range умеет считать назад, если дать ему третий аргумент",
    "range(n, 0, -1) даёт числа от n до 1"
  ],
  "solution": "def count_down(n):\n    return list(range(n, 0, -1))"
}
```

- `entry` — имя функции, которую вызывает проверка. Все задачи устроены как «напиши
  функцию»: так проверка автоматическая и заодно повторяются функции.
- `hidden: true` — тест не показывается до запуска. Один скрытый тест на задачу,
  обычно с граничным случаем. Он не даёт «подогнать под ответ» и учит думать про края.
- Задача на C# имеет **тот же `id`** и ту же формулировку, отличается `starter`,
  `solution` и типами в тестах. Именно по `id` сайт связывает решения между занятиями.

## Темы и задачи

Восемь тем, по три задачи. Идут в этом порядке.

**1. Переменные, типы, вывод** (`basics`)
Стартовый шаблон уже содержит `def`, поэтому в теории объясняется только, что
это «коробка, в которую кладут код», подробности будут в теме 7.
- `greet(name)` → строка «Привет, Аня!»
- `rectangle_area(a, b)` → площадь прямоугольника
- `seconds_to_time(sec)` → «1 ч 5 мин 3 с» из числа секунд

**2. Условия** (`conditions`)
- `is_even(n)` → True или False
- `max_of_three(a, b, c)` → наибольшее из трёх
- `grade(score)` → «отлично» / «хорошо» / «удовлетворительно» / «плохо» по диапазонам

**3. Цикл for и range** (`loops-for`)
- `sum_to(n)` → сумма чисел от 1 до n
- `count_down(n)` → список от n до 1
- `stairs(n)` → строка-лесенка из решёток с переносами

**4. Цикл while** (`loops-while`)
- `digits_count(n)` → сколько цифр в числе, без превращения в строку
- `collatz_steps(n)` → сколько шагов до единицы по правилу «чётное делим, нечётное ×3+1»
- `binary_guess(secret)` → сколько попыток нужно, чтобы угадать число от 1 до 100
  делением диапазона пополам

**5. Списки** (`lists`)
- `find_max(numbers)` → максимум без использования `max()`
- `remove_duplicates(items)` → список без повторов, порядок сохраняется
- `top3(numbers)` → три наибольших числа по убыванию

**6. Строки** (`strings`)
- `reverse(text)` → строка задом наперёд
- `count_vowels(text)` → сколько гласных, русских и английских
- `caesar(text, shift)` → шифр Цезаря

**7. Функции** (`functions`)
Здесь разбирается то, что раньше было рамкой: параметры, `return`, вызов своей функции
из другой.
- `is_prime(n)` → простое ли число
- `primes_up_to(n)` → список простых до n, **обязан вызывать `is_prime`**
- `password_strength(password)` → «слабый» / «средний» / «сильный» по трём проверкам,
  каждая вынесена в отдельную функцию

**8. Словари** (`dicts`)
- `count_letters(text)` → словарь «буква → сколько раз встретилась»
- `best_player(scores)` → имя с наибольшим счётом
- `merge_scores(a, b)` → два словаря складываются в один, общие ключи суммируются

Две задачи выбраны с прицелом на прошлый год этой группы: шифр Цезаря продолжает
их модуль «Этичный хакинг», а `binary_guess` — это алгоритм, который они уже разбирали.
Стоит упомянуть это в тексте задачи одной строкой.

За два часа группа проходит четыре-пять тем. Оставшиеся — материал для тех, кто идёт
быстрее, и для дома. Отдельного списка дополнительных заданий не нужно: сайт сам
разводит детей по темпу.

## C#-версия и сравнение с собственным кодом

Тот же сайт, те же восемь тем, те же 24 задачи, тот же UI. Отличается только язык.

На странице задачи появляется третья зона: **своё решение на Python** с прошлого
занятия, только для чтения, рядом с пустым редактором для C#. Сервер находит его
по имени ребёнка и `id` задачи.

Это и есть ответ на вопрос «чем языки отличаются» — не лекция, а собственный код
в двух колонках. Если решения на Python нет (ребёнок пропустил занятие или не дошёл
до темы), вместо него показывается эталонное решение с пометкой «пример».

Теория в C#-версии строится от отличий, а не с нуля: типы перед именами, точка
с запятой, фигурные скобки вместо отступов, `Console.WriteLine` вместо `print`,
`&&` вместо `and`, компиляция перед запуском. В каждой карточке теории — тот же пример
на двух языках рядом.

Отдельно нужна карточка про то, что говорит компилятор: `CS1002: ; expected`,
`CS1513: } expected`, `CS0029: cannot convert`, `CS1061: no definition for`.
Ошибка компилятора должна показываться ребёнку с номером строки **в его коде**,
а не в сгенерированной обёртке — при сборке файла считай смещение и вычитай его.

## Таблица прогресса

Отдельная страница `/board` для проектора.

Считается **только прогресс**: сколько задач решено, сколько тем закрыто. Время решения
не учитывается и нигде не показывается. Причина простая: если считать скорость, через
двадцать минут трое уедут вперёд, а остальные перестанут стараться. При подсчёте
по прогрессу цифра растёт у каждого.

- Строка на ребёнка: имя, полоса прогресса по восьми темам, число решённых задач.
- Сортировка по числу решённых, но без крупных номеров мест — это таблица движения,
  а не пьедестал.
- Обновление раз в 3 секунды обычным опросом. WebSocket здесь не нужен.
- Взятая подсказка снимает балл, но тему не блокирует.
- Тьютор на своей странице дополнительно видит, кто на какой задаче сидит дольше всего —
  это единственное место, где время вообще фигурирует, и видит его только он.

Проверка идёт в браузере, поэтому теоретически ребёнок может отправить на сервер
фальшивый результат через консоль. Это осознанно принятый размен: в обмен мы получаем
работу без сервера и мгновенный отклик. Таблица считает прогресс, а не победу,
так что цена накрутки невелика. Не пиши в README, что результаты защищены от подделки.

## Как это запускается

На детские компьютеры не ставится ничего. У них есть браузер.

1. Тьютор запускает сервер одной командой на своей машине.
2. Сервер печатает в консоль адрес вида `http://192.168.1.50:8000` крупно.
3. Дети открывают этот адрес.

**Отдельно про сеть.** Во многих гостевых Wi-Fi включена изоляция клиентов, и тогда
ноутбуки не видят машину тьютора вообще. Напиши это в README первым пунктом раздела
про запуск, вместе со способом проверить заранее (открыть адрес с другого ноутбука
за день до занятия) и с запасным вариантом — раздать точку доступа с телефона тьютора,
там изоляции нет.

Ngrok и туннели по умолчанию не нужны и в проекте не используются.

## UI и ощущение

Сайт должен выглядеть как инструмент, а не как школьный учебник. Детям 12–14, и разница
между «нам дали задание» и «нам дали доступ» здесь решает всё.

- Тёмная тема, моноширинный шрифт в коде, спокойный акцентный цвет. Никаких
  мультяшных иллюстраций, маскотов и восклицательных знаков.
- Подсветка синтаксиса обязательна. Редактор — CodeMirror, **вендорить локально**,
  никаких CDN: в классе может не быть интернета.
- Тесты загораются по одному с задержкой 150–200 мс. Все зелёные — короткая
  сдержанная анимация, без конфетти.
- Ошибка показывается человеческим языком и с номером строки: «Строка 4: имя `numbrs`
  не определено. Проверь, как ты назвал переменную выше». Голый traceback не показывать.
- Прогресс по темам виден всегда — узкая полоса сверху, восемь сегментов.
- Кнопка «Запустить» в примерах теории работает мгновенно, без обращения к серверу.
- Русский язык везде, включая тексты ошибок. Код и имена функций — английские.
- Страница должна нормально работать на ноутбуке с экраном 1366×768 — это самый
  вероятный класс.

## Технические требования

- Python 3.11+, FastAPI, uvicorn. `requirements.txt` на три пакета.
- .NET SDK на машине тьютора — только для C#-версии.
- Фронтенд: ванильный JS, без сборки и без фреймворков. Никаких обращений к внешним
  хостам во время работы.
- Skulpt и CodeMirror лежат в `static/vendor/`, скачиваются один раз при подготовке.
- Хранилище: SQLite-файл. Таблицы: `students`, `solutions`, `progress`.
- Задачи — JSON-файлы в `content/python/` и `content/csharp/`, по файлу на тему.
  Ни одна задача не хардкодится в коде.
- Запуск C# — процесс с таймаутом 10 секунд, во временной папке, вывод обрезается
  до 10 КБ. Это не песочница, и в README так и надо написать: рассчитано на детей
  и случайные бесконечные циклы, а не на злонамеренный код.
- Тесты на pytest: загрузка контента, проверка решений, API прогресса, компиляция C#.
- Код на английском, интерфейс и комментарии на русском.
- Отдельный скрипт `tools/check_content.py`, который прогоняет эталонные решения
  из поля `solution` через все тесты каждой задачи. Он должен запускаться в CI смысле —
  одной командой, и падать, если хоть одна эталонка не проходит. Без него ошибка
  в задаче обнаружится посреди занятия.

## Чего не делать

- Никакого ООП: ни классов, ни объектов, ни методов в теории, задачах и примерах.
- Не делать регистрацию, пароли, роли и восстановление доступа.
- Не делать редактор с автодополнением и линтером — он отвлекает и мешает
  учиться замечать свои ошибки.
- Не выводить время решения детям. Только тьютору и только на его странице.
- Не подключать ничего с CDN.
- Не хранить историю между учебными годами. Данные живут два занятия.
- Не добавлять чат, комментарии и возможность смотреть чужой код.
- Не генерировать задачи на ходу — только из JSON-файлов.

## Порядок работы

1. **Одна тема целиком, end-to-end.** Возьми тему «Условия»: JSON с тремя задачами,
   страница с теорией и редактором, Skulpt, проверка, показ тестов. Без сервера,
   без базы, без счёта — просто открывающийся файл. Покажи мне результат.
2. **Сервер, база, прогресс, таблица на проекторе.**
3. **Остальные семь тем на Python** плюс `check_content.py`.
4. **C#: раннер на сервере**, замер времени компиляции, обработка ошибок с правильными
   номерами строк.
5. **C#-контент** — те же 24 задачи — и режим сравнения с собственным решением на Python.

После каждого шага останавливайся и показывай результат. Не пиши всё сразу.

## Что должно получиться

- Тьютор запускает сервер одной командой, консоль печатает адрес крупно.
- Ребёнок открывает адрес, вводит имя, читает теорию, запускает примеры прямо в тексте.
- Решает задачу, видит, как тесты загораются по одному, и получает понятную ошибку
  с номером строки, когда что-то не так.
- Бесконечный цикл в коде ребёнка не вешает вкладку: выполнение прерывается,
  появляется сообщение «программа выполняется слишком долго, проверь условие цикла».
- Таблица на `/board` обновляется сама и показывает движение всей группы.
- Выключение сервера посреди работы не мешает решать задачи — только гаснет таблица.
- `python tools/check_content.py` проходит на всех 48 задачах.
- В C#-версии рядом с редактором видно собственное решение ребёнка на Python.

## Что спросить у меня перед началом

Прочитай документ целиком, потом задай вопросы, если что-то мешает начать:

1. Сколько детей в группе — от этого зависит вёрстка таблицы на проекторе.
2. Какая ОС на машине тьютора — от этого зависит, как оформить запуск в одну команду

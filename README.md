# Терминал

Локальный сайт для повторения языка программирования. Ребёнок читает короткую
теорию с живыми примерами, тут же решает задачи в редакторе, сайт проверяет
решение тестами. На проекторе висит общая таблица движения группы.

Две версии одного курса — на Python и на C#. Восемь тем, по три задачи, темы
и задачи совпадают один в один. На занятии по C# ребёнок видит рядом собственное
решение той же задачи на Python, которое написал неделю назад.

Учебный модуль KIBERone, старшая группа, 12–14 лет. Два занятия по два часа.

Просто хотите провести занятие? [ТЬЮТОРУ.md](ТЬЮТОРУ.md) — одна команда
и короткий гайд, без внутреннего устройства сайта.

Продолжаете работу над проектом? Начните с [NEXT.md](NEXT.md) — там состояние,
что сделать до занятия и на какие грабли я уже наступил. [CLAUDE.md](CLAUDE.md) —
полный контекст для Claude Code.

## Запуск

```
start.bat
```

Это `python start.py` — единая точка входа. Она сама ставит недостающие
библиотеки, пересобирает версию для флешки (см. ниже) и запускает сервер.
Короткий гайд без деталей устройства — [ТЬЮТОРУ.md](ТЬЮТОРУ.md).

Запустить только сервер, без остальных шагов:

```
pip install -r requirements.txt
python server/app.py
```

Сервер напечатает в консоль адрес крупно — его и открывают дети.

| Страница | Кому |
|---|---|
| `/` | ребёнку: имя и выбор языка |
| `/board` | на проектор |
| `/tutor` | тьютору |

Для занятия по C# на машине тьютора нужен .NET SDK:

```
winget install Microsoft.DotNet.SDK.8
```

**Если прав администратора нет** — а на школьном ноутбуке их часто нет —
ставится в папку пользователя, без установщика:

```
powershell -c "& { iwr https://dot.net/v1/dotnet-install.ps1 -OutFile d.ps1; ./d.ps1 -Channel 8.0 }"
```

Сервер ищет `dotnet` и в PATH, и в `%USERPROFILE%\.dotnet` — оба варианта
работают одинаково.

Без SDK Python-занятие работает полностью, а C# честно скажет, что запускать
нечем. Сервер сообщает об этом при старте.

Первый запуск после установки SDK прогревает компилятор — это занимает
полминуты и делается один раз. Дальше проверка задачи укладывается в секунду.

### Сеть в классе — прочитать до занятия

1. **Во многих гостевых Wi-Fi включена изоляция клиентов.** При ней ноутбуки
   детей не видят машину тьютора вообще, и никакая настройка сайта это не лечит.
   Проверить заранее: за день до занятия открыть адрес вида
   `http://192.168.x.x:8000` с другого ноутбука в той же сети.
2. **Запасной вариант** — раздать точку доступа с телефона тьютора и подключить
   к ней машину тьютора и детские ноутбуки. В личной точке доступа изоляции нет.
3. Ngrok и туннели не нужны и в проекте не используются.

На детские компьютеры не ставится ничего: у них есть браузер.

**Если раздать сайт по адресу вообще не получится** — например, изоляцию клиентов не отключить, — есть версия для флешки: только Python, без сервера и сети, открывается двойным кликом на каждом ноутбуке отдельно. Собрать:

```
python tools/build_offline.py
```

Подробности: [docs/ОФЛАЙН.md](docs/ОФЛАЙН.md).

## Проверка контента

```
python tools/check_content.py
```

Прогоняет эталонные решения из поля `solution` через все тесты каждой задачи
и падает, если хоть одна эталонка не проходит. Запускать после любой правки
задач: иначе ошибка обнаружится посреди занятия.

Решения на C# при этом компилируются по-настоящему. Если .NET SDK не установлен,
команда не притворяется успешной — она сообщает, что C# не проверен, и падает.

Тесты:

```
pip install -r requirements-dev.txt
python -m pytest tests -q
```

Проверяют загрузку контента, эталонные решения, API прогресса, соответствие
двух языков один в один и разбор ошибок компилятора. Тесты, которым нужен
.NET SDK, пропускаются, если его нет.

## Устройство

```
terminal/
├── server/
│   ├── app.py              FastAPI: статика, прогресс, запуск C#
│   ├── db.py               SQLite: students, solutions, progress
│   ├── runner_csharp.py    компиляция и запуск C#
│   └── static/             страницы, стили, вендоренные Skulpt и CodeMirror
├── content/
│   ├── python/             8 тем по 3 задачи
│   └── csharp/             те же id
├── tools/
│   ├── check_content.py    прогон эталонных решений
│   ├── make_solutions.py   собирает docs/РЕШЕНИЯ.md для тьютора
│   └── shot.js, probe.js   снимок и проба страницы в headless Chrome
├── docs/
│   ├── ЗАДАНИЕ.md          исходное задание
│   └── РЕШЕНИЯ.md          все 48 решений, шпаргалка тьютора
├── tests/
└── start.bat
```

Ни одна задача не зашита в код. Тема — это один JSON-файл: заголовок, карточки
теории с запускаемыми примерами и три задачи. У задачи есть стартовый шаблон,
имя функции для проверки, тесты, две-три подсказки и эталонное решение.

Один тест в каждой задаче помечен `"hidden": true`. Он не показывается до
проверки, обычно это граничный случай. Так решение нельзя подогнать под ответ,
и ребёнок привыкает думать про края диапазона.

Часть задач помечена `must_call`: например, `primes_up_to` обязана вызывать
`is_prime`, а не проверять делимость заново. Это единственное требование,
которое тестами по результату не поймать, поэтому оно проверяется по исходнику
и показывается отдельной строкой в списке тестов.

## Что видит ребёнок

**Пример теории можно пройти по шагам.** Рядом с «Запустить» стоит кнопка
«По шагам»: программа останавливается перед каждой строкой, строка
подсвечивается, а под кодом показываются коробки с переменными — те самые,
про которые говорит первая карточка теории. Видно, как значение меняется
и как цикл проходит одну и ту же строку несколько раз. Есть «До конца»,
«Сначала» и «Выйти».

Коробка, которую только что изменила выполненная строка, подсвечивается —
это и есть ответ на вопрос «что сделала эта строка». Фокус остаётся
на кнопке «Шаг», так что пройти программу можно, просто удерживая Enter.

Шаги работают только для Python: он выполняется прямо в браузере. На занятии
по C# рядом с каждым примером стоит его двойник на Python — кнопка шагов
живёт там, и это тот же самый алгоритм.

**Задачу можно отложить.** Если задача не идёт, кнопка «Отложить» уводит
на следующую, а отложенная остаётся в списке с контурной пометкой и ждёт.
Она не пропадает и не засчитывается: когда свободных задач не остаётся,
сайт сам предлагает вернуться именно к ней. Смысл простой — одна трудная
задача не должна останавливать всё занятие.

**Отложенные задачи открывают следующую тему.** Разобрался с темой как мог —
что-то решил, что-то отложил — следующая открыта. Три отложенные задачи
работают здесь так же, как три решённые: дети идут вперёд с тем, что им
по силам.

При этом в прогрессе отложенное не засчитывается никогда. Это два разных
счёта, и они не путаются: насечки в шапке, счётчик `0/24` и таблица
на проекторе показывают только решённое, а отложенная задача рисуется
контуром — видно по всему курсу, куда стоит вернуться.

**Ответ засчитывается по тому, что функция вернула.** Под условием каждой
задачи висит строка, которая прямо это говорит. Самая частая путаница
первого занятия — напечатать ответ вместо того, чтобы его вернуть: внизу
стоит правильный текст, а все тесты красные. Этот случай узнаётся отдельно,
и вместо «получилось None» сайт объясняет разницу между `print` и `return`.

**Тёмная и светлая темы.** Переключаются кнопкой в шапке на любой странице,
выбор запоминается. Фирменные жёлтый и бирюза остаются на месте в обеих.

## Решения, принятые по дороге

**Python исполняется в браузере, C# — на сервере.** Skulpt весит около мегабайта
и лежит локально. Отсюда главное свойство: урок не умирает вместе с сервером.
Если сервер упал или пропала сеть, дети продолжают решать Python — гаснет только
общая таблица, и сайт прямо об этом говорит плашкой. Отправки прогресса ждут
в очереди и уходят, когда сервер вернётся.

**Pyodide не используется** — он честнее, но это 10+ МБ на каждого ребёнка через
один классный Wi-Fi. Для задач этого курса Skulpt достаточен. Blazor и Roslyn
в браузере по той же причине не используются: C# компилируется на машине тьютора.

**Бесконечный цикл не вешает вкладку.** У Skulpt стоит лимит времени, у C#
процесс снимается через десять секунд. В обоих случаях ребёнок видит:
«Программа выполняется слишком долго. Скорее всего, цикл никогда не заканчивается».

**Голый traceback детям не показывается нигде.** Ошибки Python переводятся
на человеческий язык с номером строки. Ошибки компилятора C# показываются
с номером строки **в коде ребёнка**: заготовка с вызовами тестов приписывается
после его кода, поэтому его строки не сдвигаются ни на одну.

**Никакого ООП** — ни классов, ни объектов, ни методов в теории, задачах
и примерах. В C# `class Program` присутствует как обязательная рамка языка,
и в теории подаётся именно так: рамка, внутри которой мы пишем функции.
Впереди у группы 12 занятий C#, где это разбирается с нуля.

**Ничего не грузится с CDN.** В классе может не быть интернета.

**Проверка идёт в браузере, поэтому результат можно подделать через консоль.**
Это осознанный размен: взамен получаем работу без сервера и мгновенный отклик.
Таблица считает прогресс, а не победу, так что цена накрутки невелика.

**Запуск C# — не песочница.** Расчёт на детей и случайные бесконечные циклы,
а не на злонамеренный код: процесс ограничен по времени, вывод обрезается
до 10 КБ, работа идёт во временной папке. Чтобы компиляция не занимала
секунды на каждую проверку, сервер держит пул готовых проектов и подменяет
в них один файл; пул заодно ограничивает число одновременных сборок.

## Таблица группы

Считается **только прогресс**: сколько задач решено, сколько тем закрыто. Время
решения детям не показывается нигде. Причина простая: если считать скорость,
через двадцать минут трое уедут вперёд, а остальные перестанут стараться.
При подсчёте по прогрессу цифра растёт у каждого.

Сортировка по числу решённых, но без крупных номеров мест: это таблица движения,
а не пьедестал. Обновление раз в три секунды обычным опросом.

Время фигурирует ровно в одном месте — на странице тьютора, в списке «кто где
сидит». Открывать код конкретного ребёнка страница не умеет: по решению
заказчика тьютору достаточно видеть прогресс.

**Лишнее имя убирается со страницы тьютора.** У каждой строки есть кнопка
«Удалить»; она спрашивает подтверждение и только потом стирает. Нужно это
после проб и опечаток: «Никита», «Никитаа» и «НикитааА» на проекторе мешают
видеть группу.

Удаление необратимо и уносит ребёнка целиком — прогресс и решения на обоих
языках. Половину удалить нельзя намеренно: решение на Python ребёнок увидит
рядом с задачей на занятии по C#, и стереть его значит тихо сломать вторую
половину курса. Удалять умеет только тот, кто ввёл пароль.

Один нюанс: если удалить ребёнка, который прямо сейчас сидит за ноутбуком,
он вернётся в таблицу при следующей сданной задаче — его собственный прогресс
хранится ещё и в браузере. Для чистки лишних профилей это не мешает.

Данные живут два занятия и стираются. Истории между учебными годами нет.
Ребёнок никакого пароля не вводит — только имя, один раз.

**Таблица группы и страница тьютора закрыты паролем `admin123`.** Он спрашивается
один раз, вход держится 12 часов, на странице тьютора есть кнопка «Выйти».
Свой пароль задаётся переменной окружения перед запуском:

```
set TERMINAL_PASSWORD=свой-пароль
python server/app.py
```

Это заслон от любопытного ребёнка, а не настоящая защита: занятие идёт
по обычному http внутри класса, и пароль ходит по сети открытым текстом.
Закрыт и сам адрес `/api/tutor`, а не только страница, — иначе время решения
можно было бы прочитать в обход.

## Оформление

Фирменные цвета KIBERone взяты из `logo_kiberone.pdf`: жёлтый `#F9CA00`,
бирюза `#0BB4B9`, глубокий синий `#004F6A`.

Правило палитры: **жёлтый — сигнальный цвет состояния**. Он показывает «где я
сейчас» и «что сейчас произошло», и не используется для украшения. Бирюза —
цвет «провода»: прогресс, фокус, пройденный тест. Зелёного в бренде нет, и он
не нужен: пара бирюза/красный вдобавок различима при дальтонизме, а форму несут
значки `✓` и `✕`.

Типографика построена на одном правиле: **машина говорит моноширинным, человек —
гротеском**. Метки, числа, имена функций и кнопки — Consolas; проза теории —
Segoe UI. Шрифты только системные, потому что в классе может не быть интернета.

Индикатор курса в шапке — восемь сегментов по три насечки, то есть буквально
восемь тем по три задачи. Тот же язык насечек повторён на «шине» слева, которая
соединяет карточки теории.

Когда задача сдана, по панели тестов один раз проходит жёлтая строка развёртки,
рамка защёлкивается, встаёт штамп, и наверху загорается новая насечка курса.
Одна собранная секунда, без конфетти.

Целевой экран — ноутбук 1366×768.
